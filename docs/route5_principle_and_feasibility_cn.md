# Route5 原理、最佳结果与实验可行性说明

## 1. 一句话结论

`route5` 可以把

```text
高速连续变量（CV）接收前端
+ 数字离散化
+ route2 的单设备 MDI 认证
```

拼在一起。

它的核心价值是：

- 安全模型里最终输出仍然是离散的；
- 但物理前端不需要退回到低速单光子点击探测；
- 因此它从原理上避开了“单光子探测器死时间把采样速率卡到 MHz”的主要瓶颈。

当前原型里，`route5` 已经得到

```text
H_min ≈ 2.11639
```

说明它在“保持高速 CV 前端的同时，把认证最小熵推到 2 bit 以上”这件事上，已经有了明确的数值可行性证据。

如果进一步把条件收紧到更贴实验限制的情形：

```text
只允许使用光强集合 [0,80,160]
```

那么在当前的比例保持映射下，`route5` 仍然得到

```text
H_min ≈ 2.10102
```

所以从“受限光强菜单下还能不能过 2”这个角度看，当前答案仍然是能。

---

## 2. Route5 到底是什么

如果用最通俗的话说，`route5` 做的事情是：

1. 不再用“单光子来了没来”的点击方式读出；
2. 而是先用高速 IQ / dual-homodyne 接收机，把每一轮测量变成一对连续数值 `(I,Q)` 或 `(x,p)`；
3. 然后在数字端把这些连续值切成有限个区域，也就是“分箱”；
4. 每个区域对应一个离散输出 `c`；
5. 最后把这个离散输出统计 `P(c|x,y)` 送进 route2 的单设备 SDP，计算 Eve 的最优猜测概率，再得到
   `H_min = -log2(p_guess)`。

所以 route5 的本质不是：

```text
“完全连续变量的安全证明”
```

而是：

```text
“连续变量硬件前端 + 离散输出安全认证”
```

这是它和 route3、route2 都不完全一样的地方。

---

## 3. 为什么要做 Route5

### 3.1 它想同时解决两件事

之前几条路线各有优缺点：

- `route2` 的安全结构很干净，但人们很容易把它联想到“离散单光子方案”，担心速率慢；
- `route3` 的硬件图像更像高速 CV 实验，但当前 phase-only 输入集太弱，认证值上不去。

`route5` 就是在两者中间搭桥：

- 硬件端尽量保留 `route3` 的高速 CV 前端；
- 安全分析端尽量保留 `route2` 的单设备 MDI SDP；
- 同时把 trusted input 从“只扫相位”升级成“振幅和相位一起扫”的更强字母表。

### 3.2 它要解决的真正矛盾

很多讨论里会把下面两件事混在一起：

1. 安全证明里最终输出是离散的；
2. 物理上必须用低速单光子探测器做离散点击。

实际上这两件事不是一回事。

`route5` 的关键观点是：

```text
离散安全模型 != 必须用单光子点击读出
```

你完全可以：

- 前端用高速模拟接收机；
- 后端再做数字离散化；
- 最后对离散结果做随机性认证。

## 4. 关键术语到底是什么意思

## 4.1 Coherent State 是什么

相干态可以把它理解成“最接近经典激光脉冲的量子态”。

它通常用一个复数 `alpha` 表示：

```text
alpha = r * exp(i * phi)
```

这里：

- `r = |alpha|` 是振幅大小；
- `phi` 是相位；
- `|alpha|^2` 与平均光子数或光强成正比。

所以：

- 改 `r`，就是改“亮不亮”；
- 改 `phi`，就是改“相位朝向”。

在相空间里，一个相干态就像一个点。

## 4.2 Coherent Alphabet 是什么

`alphabet` 可以直译成“字母表”。

在 route5 里，它的意思就是：

```text
实验允许拿来当输入态的一组相干态集合
```

比如：

- 真空态 `alpha = 0`
- 半径 `0.85` 上的 8 个相位点
- 半径 `1.25` 上的 8 个相位点

合在一起，就是一个 `17` 态的本地字母表。

当前最好点就是这种结构：

- `1` 个真空态
- `8` 个 `r = 0.85` 的相干态
- `8` 个 `r = 1.25` 的相干态

总共 `17` 个本地输入态。

因为 Alice 和 Bob 都从同一个本地字母表里选，所以联合输入共有：

```text
17 × 17 = 289
```

个输入对 `(x,y)`。

如果实验上不能任意选半径，而是只允许固定光强菜单，例如：

```text
|alpha|^2 ∈ {0, 80, 160}
```

那么 route5 就不能随便给 `r`，而要把光强菜单映射成半径菜单。

因为

```text
|alpha|^2 ∝ intensity
```

所以在当前原型里采用的是“保持光强比例不变”的映射：

```text
radius = max_radius * sqrt(intensity / max_intensity_in_menu)
```

例如取 `max_radius = 1.2` 时，有：

```text
[0, 80, 160]  ->  [0, 0.848528..., 1.2]
```

这就是后面那个 `[0,80,160]` 受限结果的来源。

## 4.3 为什么 route5 不再满足于 phase-only

`route3` 主要是“固定振幅，只扫相位”。

这意味着所有输入态都落在相空间同一个圆环上。

这样做的缺点是：

- 输入态虽然很多；
- 但它们对未知测量的约束方向不够丰富；
- Eve 仍然会保留很多“看不见的自由度”。

`route5` 改成“振幅 + 相位一起扫”之后，相空间点不再只落在一个圆上，而是覆盖多个半径层。

直观上说，就是：

```text
不只是在同一个圆周上取点，
而是在二维相空间里铺得更开。
```

这会让 trusted inputs 的约束能力明显变强。

## 4.4 IQ Search 是什么

`IQ Search` 可以理解成：

```text
在 I/Q 平面上找最合适的数字分箱方法
```

更准确地说，route5 假设中央前端是：

- beam splitter
- dual-homodyne / heterodyne

测完以后，每一轮得到两个连续数值，可以记成：

- `I` / `Q`
- 或 `x` / `p`

这些数值本来是连续的，但 SDP 最后要吃的是离散输出 `c`。

所以 route5 会做一件事：

- 把 `x` 轴切成若干段；
- 把 `p` 轴切成若干段；
- 两个方向的组合区域，共同定义离散输出。

例如当前最好点里：

- `x` 轴分成 `6` 段；
- `p` 轴分成 `2` 段；
- 所以总输出数是
  `6 × 2 = 12`。

这就是图里常写的：

```text
6 x 2 IQ partition
```

## 4.5 quadrature_range 和 gamma 是什么

这两个量是 route5 里“怎么切分 IQ 平面”的参数。

### `quadrature_range`

它控制中间有限区域的大概宽度。

比如当前最好点 `quadrature_range = 1.8`，意味着：

- 中间细分区域主要集中在 `[-1.8, 1.8]` 附近；
- 再往外的部分并到两边无穷尾区。

### `gamma`

它控制边界是“均匀分”还是“往中心挤得更密 / 往边缘挤得更密”。

当前最好点里：

```text
gamma = 1.0
```

这对应的是基本均匀的幂律分箱。

在该点下，`x` 轴边界正好是：

```text
[-∞, -1.2, -0.6, 0, 0.6, 1.2, +∞]
```

而 `p` 轴边界是：

```text
[-∞, 0, +∞]
```

所以你可以把当前最好点理解成：

- 在 `x` 方向做了更细的 6 段切分；
- 在 `p` 方向只做了正负两半的粗切分。

## 5. Route5 的完整计算流程

把 route5 代码真实在做的事情翻成白话，大致是这 7 步：

1. 先指定一批候选相干态输入
   - 也就是选哪些 `alpha = r e^{i\phi}` 可以当 trusted inputs。
2. 把这些输入态投影到它们真正张成的支撑子空间
   - 这样可以减小数值维度。
3. 固定中央物理前端
   - 使用 beam splitter + dual-homodyne。
4. 枚举很多种 IQ 分区方式
   - 也就是很多种 `(x,p)` 数字分箱方案。
5. 对每种方案先算一个 raw 指标
   - 相当于先看“只看观测分布时，它看上去随机不随机”。
6. 只把最有希望的 top-k 候选送去正式 SDP
   - 这是为了节省大量求解时间。
7. 用 route2 的单设备 guessing-probability SDP 做 formal 认证
   - 得到最终的 `p_guess` 和 `H_min`。

其中最重要的一点是：

```text
route5 的 formal 认证后端，
和 route2 是同一类 single-device MDI SDP。
```

所以 route5 并不是“另起炉灶搞一个全新安全证明”，而是：

- 改了输入字母表；
- 改了统计生成方式；
- 但保留了 route2 那套正式认证框架。

## 7. 这些参数为什么会比较好

从目前搜索结果看，当前高分点有几个共同特征。

### 7.1 两个非零半径比单一半径更好

只用一个非零半径时，输入仍然太像“单圆 phase-only”结构。

加入第二个非零半径之后，trusted alphabet 的几何结构更丰富，对未知中央测量的约束更强。

### 7.2 `6 x 2` 比“更平均”的分法更好

当前最好点不是 `4 x 4`，而是 `6 x 2`。

直观理解是：

- 有用的区分信息并没有在两个轴上平均分布；
- 在更有信息的一轴上多给一点分辨率；
- 在较弱的一轴上只做粗分，
  反而更有利于 formal 认证。

### 7.3 最优 formal target 不一定等于 raw-best target

我们后来专门做过多 target input 认证，发现：

```text
raw 看起来最随机的输入，
不一定就是 formal 认证后最好的输入。
```

这也是为什么 route5 后来改成：

- 先挑前若干个 raw 最有希望的目标输入；
- 再逐个做 SDP；
- 最后取 formal 最优。

这个改动是重要的，不是装饰性的。

## 8. Route5 在实验上可行吗

## 8.1 原理上可行，而且比“离散单光子版 route2”更贴近高速目标

如果实验室想要的是：

- 高速采样；
- 尽量远离单光子死时间瓶颈；
- 同时又不放弃 formal 认证，

那 route5 在方向上是合理的。

因为它的物理前端不是：

- APD click/no-click；
- 或单光子偏振点击计数；

而是：

- 线性光学混合；
- 平衡探测；
- 模拟信号；
- 高速 ADC；
- 数字分箱。

因此它不会天然被“单光子探测器死时间 = MHz 量级”卡住。

## 8.2 它需要实验上真的做什么

要把 route5 落成实验，大体上需要下面这些模块：

1. Alice 和 Bob 两边的可信相干态制备
   - 能稳定地打出预定的振幅和相位。
2. 中央 beam splitter + dual-homodyne / heterodyne 接收
   - 输出两路连续模拟量。
3. 高速采样和数字处理
   - 把模拟波形变成每轮的 `x,p` 或 `I,Q` 数值。
4. 数字 coarse-graining
   - 用预先选定的边界把每轮样本映射成离散输出 `c`。
5. 测试轮统计采集
   - 估计所有需要的 `P(c|x,y)`。
6. 后端 formal SDP
   - 输入实验统计和可信输入信息，输出 `H_min`。

最关键的一个实验友好点是：

```text
中央测量不需要真的物理实现一个“自由的 12 输出任意 POVM”，
只要实现高速 IQ 接收，再在数字端做 12 类分箱即可。
```

这一点比 route2 的“自由高输出 POVM”图像要更容易想象得多。

## 9. Route5 的主要风险是什么

## 9.1 风险一：当前最好结果还是理论原型，不是实验回放

现在 route5 的 `H_min > 2` 是怎么来的？

答案是：

- trusted input 由理论模型生成；
- IQ 测量统计 `P(c|x,y)` 也由理论模型生成；
- 然后再送进 SDP。

所以它是“协议-硬件共设计原型”的最好结果，不是“已经用实验数据重放出来的值”。

这并不削弱它的可行性意义，但要说清楚口径：

```text
它已经证明“这条结构路线能通”，
但还没有证明“实验现成数据已经达到这个值”。
```

## 9.2 风险二：需要同时控制振幅和相位

route5 的输入字母表比 route3 更强，但也更难做。

因为 route3 更像：

- 一圈点，主要控制相位；

而 route5 更像：

- 多圈点，同时控制振幅和相位。

这会带来：

- 调制器线性度要求更高；
- 相位漂移更敏感；
- 振幅标定更重要；
- 不同输入态之间的串扰更值得警惕。

## 9.3 风险三：测试输入变多，统计采集压力会变大

当前最好点的本地字母表有 `17` 个态，因此联合输入有 `289` 个。

这不意味着生成轮一定要平均用完 289 个输入对，但它意味着：

- 测试轮如果想完整复现当前模型，就要覆盖很多输入组合；
- 参数估计和有限尺寸开销会明显上升。

所以 route5 的一个真实代价是：

```text
输入结构更强了，
但测试和标定工作量也更大了。
```

## 9.4 风险四：高速不等于“已经得到 10 Gbps 认证输出”

route5 规避的是：

```text
单光子点击死时间瓶颈
```

但它没有自动解决：

- ADC 相关性；
- 模拟带宽限制；
- 时钟定义一轮的方式；
- 生成轮 / 测试轮比例；
- 有限尺寸；
- 提取器损耗。

所以更准确的说法是：

```text
route5 使高速成为可能，
但还没有自动把“高速前端”变成“最终认证比特率”。
```

## 10. 到底需不需要额外数据

这是最容易被问到、也最需要分情况回答的问题。

## 10.1 如果只是做理论参数搜索：不需要额外实验数据

如果你的目标只是：

- 分析 route5 的原理；
- 找到最有希望的 alphabet 和 IQ 分区；
- 看看在物理模型下 `H_min` 能不能超过 `2`，

那么：

```text
不需要额外实验数据。
```

尤其是对“只允许光强 `[0,80,160]`”这个受限情形来说，当前我们已经做的是：

- 先把光强菜单映射成受限半径菜单；
- 再在这个受限 alphabet 上跑 formal SDP；
- 得到 `H_min ≈ 2.10102`。

所以在“只限制光强菜单，但暂时不要求实验数据回放”的口径下，这个问题已经被回答了。

因为当前 route5 的数值流程本来就是：

- 用理论模型直接生成 `P(c|x,y)`；
- 再做 formal SDP。

所以作为“理论可行性研究”，它已经可以独立完成。

## 10.2 如果想说“实验上也成立”：需要，而且不是 Probability.mat 那种数据

如果你的目标变成：

```text
不是只看理论模型，
而是要用真实实验数据去认证 route5
```

那就必须有新的实验数据。

而且需要强调：

```text
当前的 Probability.mat 不能直接拿来做 route5。
```

原因很简单：

- `Probability.mat` 是 route4/APD 路线的数据；
- 它本质上是 `9 x 256` 的一维概率表；
- 对应的是固定光强下的 APD 输出统计；
- 没有 route5 所需的二维 IQ / dual-homodyne 信息；
- 也没有完整的相位标签。

所以 route5 真正需要的是“route5 版本的数据”。

也就是说，现阶段应这样区分：

- 如果你要回答：
  “在光强被限制为 `[0,80,160]` 时，route5 从理论上还能不能过 2？”
  那当前结果已经回答了：能。
- 如果你要回答：
  “实验上真实采出来的数据，在 `[0,80,160]` 时到底是多少？”
  那就必须采新的 IQ 数据。

## 10.3 Route5 真正需要哪些额外数据

如果要做实验版 route5，最少应准备下面几类数据。

### 1. 每个测试输入对 `(x,y)` 的 IQ 原始样本或二维直方图

最理想的是原始 `I,Q` 时间序列。

如果做不到，至少也要有：

- 在每个 `(x,y)` 条件下；
- 每个 IQ 分箱区域对应的经验频率；
- 也就是实验版的 `P_exp(c|x,y)`。

### 2. 输入态标定数据

要知道每个 trusted input 真正对应的：

- 振幅 `r`
- 相位 `phi`
- 或 `alpha`

否则“trusted alphabet”这个前提站不住。

### 3. 分箱边界与 ADC 定义

必须明确：

- 每轮样本是怎么从连续波形里抽出来的；
- `x,p` 是怎么归一化的；
- bin 边界到底放在哪里；
- 是否做了数字滤波、重采样或去直流。

因为这些处理都会改变最终的 `P(c|x,y)`。

### 4. 相关性与独立轮次判断

如果想把采样速率转成“每秒多少认证轮次”，还需要：

- 时间相关性分析；
- 自相关或互相关检查；
- 一轮到底对应一个脉冲、一个符号还是一个 ADC 样点的定义。

否则只能说“前端带宽很高”，不能直接说“认证轮次就是这么高”。

### 5. 有限尺寸所需的计数数据

当前 route5 原型主要使用的是理想概率。

如果要做真正实验认证，还需要：

- 每个输入对的总样本数；
- 每个输出 bin 的真实计数；
- 测试轮占比；
- 置信区间处理。

也就是说，需要的是“概率 + 样本数”，而不只是归一化后的概率。

## 10.4 能不能完全不需要新数据

只有在下面这个口径下才可以说“可以不需要”：

```text
我们当前只做理论可行性分析，
不宣称已经完成实验认证。
```

如果你要把 route5 写成实验方案，并声称“实验上确实能达到某个 H_min”，那就不能省掉新数据。

## 11. 目前最合理的结论怎么表述

我建议把 route5 的结论表述成下面这样，会最稳妥：

```text
Route5 不是单光子点击式离散方案，
而是“高速 CV 前端 + 数字 coarse-graining + route2 单设备 SDP”的混合路线。
它在当前理论原型中，既得到了全局最好值 H_min ≈ 2.116，
也在更贴实验限制的 `[0,80,160]` 光强菜单下得到了 H_min ≈ 2.101。
这说明这条结构路线本身是可行的，
并且从原理上规避了单光子探测器死时间导致的 MHz 级速率瓶颈。

但当前结果仍然主要是模型生成统计下的 formal 认证值。
如果要把它进一步落成实验结论，
还需要采集与 route5 匹配的 IQ / dual-homodyne 数据，
而不能直接沿用 route4 的 Probability.mat。
```

## 12. 最后给一个最简版总结

如果只记 4 句话，可以记下面这版：

1. `route5` 是“高速 CV 接收机 + 数字离散输出 + route2 的 formal SDP”。
2. `Coherent Alphabet` 就是实验允许发送的一组相干态输入；`IQ Search` 就是寻找最合适的 I/Q 数字分箱方式。
3. 如果重点看实验受限情形 `[0,80,160]`，当前最该引用的结果是：
   `radii = [0, 0.8485, 1.2]`、8 相位、`6 x 2` 分区、`range = 1.8`、`gamma = 1.0`，
   得到 `H_min ≈ 2.10102`。
4. 如果只是做理论参数搜索，不需要额外实验数据；如果要做真正实验认证，就必须采集 route5 专属的 IQ 数据，而不是继续使用 `Probability.mat`。
