# Route4-ex 冲击 `H_min >= 2` 的可行性判断

## 1. 结论先行

基于当前 `route4-ex` 的代码、现有 [`../src/matlab/Probability.mat`](../src/matlab/Probability.mat) 数据、以及最近完成的高值稳定带与残差检查，我的判断是：

1. `route4-ex` 作为“把 route4 主线推进到 `H_min >= 1`”的方案，已经很成功；
2. 当前正式可确认主结果已经达到约 `1.54 bit`；
3. 但如果目标升级为 `H_min >= 2`，那么在**当前这套数据 + 当前这条 3 输入 / 3 输出 / APD coarse-graining 主线**下，继续通过局部微调直接冲到 `2 bit` 的希望不大；
4. 若后续仍希望认真冲击 `2 bit`，需要的更像是**结构性升级**，而不是继续细抠当前稳定带。

一句话概括：

- `route4-ex` 现在已经是一条强的 `>1 bit` 路线；
- 但它还不像一条“只差一点点就能到 2 bit”的路线。

---

## 2. 当前已经达到什么位置

当前最强正式结果见：

- [`../output/qrng_routes/route4_ex_pathology_boundary_scan_q419over1024_to_q105over256_2pt.json`](../output/qrng_routes/route4_ex_pathology_boundary_scan_q419over1024_to_q105over256_2pt.json)

对应参数：

- 窗口 `[100,120,140]`
- `3` 输出边界 `[0,121,132,256]`
- 相位模式 `0_pi2_pi`
- 偏置 `q=[1,0,0]`
- `free_monotone_radii`
- 半径 `[0.5379541015625, 0.6620458984375, 0.7179541015625]`
- `MOSEK optimal`
- `H_min ≈ 1.54395`

并且这不是单点偶然。邻近点例如：

- [`../output/qrng_routes/route4_ex_pathology_boundary_scan_q209over512_to_q105over256_2pt.json`](../output/qrng_routes/route4_ex_pathology_boundary_scan_q209over512_to_q105over256_2pt.json)

也给出：

- `MOSEK optimal`
- `H_min ≈ 1.53846`

所以当前可信说法不是“我们有一个 1.54 的幸运点”，而是：

- 在当前主线下，已经存在一段 `MOSEK` 可确认的高值稳定带；
- 其正式值大约在 `1.53 ~ 1.54 bit`。

---

## 3. 为什么我不看好靠当前主线直接到 `2 bit`

### 3.1 距离并不小

从 `1.54 bit` 到 `2 bit`，差距仍有约 `0.46 bit`。

这不是“再微调一点半径”通常能拿到的提升量。  
尤其是当前我们已经为了把正式值从 `1.23` 推到 `1.54`，做了：

- 局部半径精修；
- 病态边界定位；
- 稳定/失稳阈值二分；
- 残差与可行性余量检查。

这意味着当前主线已经被推到了比较极限的位置。

### 3.2 当前高值带非常窄

根据：

- [`./route4_ex_threshold_and_residual_check_cn.md`](./route4_ex_threshold_and_residual_check_cn.md)

当前 `MOSEK` 稳定/失稳转折已经被压到一个极小窗口：

- 稳定：`[0.5379541015625, 0.6620458984375, 0.7179541015625]`
- 失稳：`[0.53795166015625, 0.66204833984375, 0.71795166015625]`

这说明：

- 当前主线不是处在一个宽阔平台上；
- 而是贴着 full-primal 的病态边界在走。

在这种情况下，继续靠“向前贴一点点”去多拿接近 `0.5 bit`，成功概率很低。

### 3.3 输出结构和输入结构都已经比较吃紧

当前最强主线是：

- 3 个输入态；
- 3 个 coarse-grained 输出；
- 偏置 `q=[1,0,0]`；
- 现有 `Probability.mat` 数据；
- APD 风格离散计数接口。

这套结构已经比原始 route4 强很多，但它本质上仍然是一个相对“瘦”的 route4 扩展版，而不是更强的 coherent alphabet 路线。

换句话说：

- `route4-ex` 已经把“在现有 APD 接口上尽量加强 trusted input”这件事做得比较到位了；
- 但它还没有进入 route5 / route6 那种“输入字母表和安全约束一起显著增强”的区间。

---

## 4. 为什么当前结果仍然有价值

虽然我不看好当前主线直接到 `2 bit`，但这并不意味着 `route4-ex` 只是个过渡失败方案。

相反，它现在有三项明确价值：

1. 它证明了：只要把 trusted inputs 从原始 route4 的 Fock 对角模型提升到非对角 coherent inputs，正式值可以从很低水平显著抬高到 `>1.5 bit`；
2. 它仍然复用了现有 `Probability.mat` 和 APD coarse-graining 接口，这对实验连续性非常重要；
3. 它为后续讨论“为什么 route4 体系仍然难到 `2 bit`”提供了一个清晰的结构性证据，而不是只靠口头判断。

因此，`route4-ex` 的现实定位更像：

- 一条已经成功突破 `1 bit`、并把 APD 主线推到约 `1.54 bit` 的增强路线；
- 而不是当前最有希望直冲 `2 bit` 的路线。

---

## 5. 若仍希望冲 `2 bit`，最值得改什么

如果后续实验室仍然希望把 route4-ex 体系继续向 `2 bit` 推，我认为最值得考虑的是下面几类结构性升级。

### 5.1 增强 trusted-input 字母表

当前只有 3 个 trusted inputs，而且虽然已经允许非对角 coherent states，但字母表规模仍然偏小。

更可能有效的方向是：

- 增加输入态数；
- 系统化设计半径和相位，而不是只在 3 个输入上做局部精修；
- 引入更强的 coherent alphabet 设计。

这是我认为最重要的一条。

### 5.2 改输出离散化，而不是只固定当前 3 输出边界

当前最强主线绑定在：

- `3` 输出边界 `[0,121,132,256]`

这条边界显然很强，但也显然很贴病态边界。  
如果要继续冲更高值，不能只继续磨这组边界，更合理的是：

- 搜索更结构化的 coarse-graining；
- 同时把“formal feasibility”一起纳入目标，而不是只看 distribution-only 熵。

### 5.3 争取更强的数据，而不是死守现有 Probability.mat

当前这套结果已经说明：

- `Probability.mat` 足够支撑 `route4-ex` 到 `1.54 bit`；
- 但是否还足够支撑 `2 bit`，我持保留意见。

如果实验室后续能提供：

- 更多输入态对应的概率行；
- 更细致的输入标定；
- 或更适合非对角 trusted-input 分析的实验数据；

那么 route4-ex 继续抬高的空间会更真实。

### 5.4 与 route5 / route6 的思路靠拢

如果目标明确写成 `H_min >= 2`，那就不能只盯着“route4 的增强版”，而要认真考虑：

- 更强 coherent alphabet；
- 更强 trusted-input 几何约束；
- 更适合高熵认证的输出离散化。

这也是为什么从项目全局角度看，我依然会认为：

- route4-ex 是一条很强的 `>1` bit 主线；
- 但真想冲 `2 bit`，更自然的希望仍然在 route2/5/6 一类更强结构上。

---

## 6. 当前最诚实的判断口径

我建议后续对导师或实验室使用这样的说法：

1. `route4-ex` 已经把原始 route4 从低熵主线推进到了 `MOSEK` 正式确认约 `1.54 bit` 的水平；
2. 当前这批高值点已经过了残差检查，可以作为正式结果；
3. 但它们位于一条非常窄的稳定前沿附近，因此这条路线当前更像“把 APD 主线推到了很强的 `>1 bit` 区域”，而不是“只差最后一步就能到 `2 bit`”；
4. 如果未来要认真冲击 `2 bit`，应优先考虑 trusted-input 字母表、输出离散化和实验数据接口的结构性升级。

---

## 7. 建议的后续工作顺序

如果当前阶段不想再盲目扩大战线，我建议按下面顺序推进：

1. 先把 `1.54 bit` 的正式主结果、病态边界定位和残差检查整合进总报告；
2. 把 `route4-ex` 明确定位成“已完成 `>1 bit` 目标的 APD 增强主线”；
3. 再决定是否要为 `2 bit` 单独立一个下一阶段课题，而不是把它默认为当前主线的自然下一步；
4. 如果真的要立这个课题，就优先设计“增强 trusted-input 字母表 / 更强输出离散化 / 更强实验数据”的升级版本。

---

## 8. 一句话总结

`route4-ex` 现在已经足够强，可以把正式结果写到约 `1.54 bit`；  
但如果问题是“沿当前主线再抠一抠，能不能直接到 `2 bit`”，我的判断是：希望不大。  
如果真要冲 `2 bit`，需要的更像是下一代结构升级，而不是继续细抠当前这条窄稳定带。
